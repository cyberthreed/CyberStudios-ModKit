# ✦ Security Policy

CyberStudios takes security reports seriously.

This repository contains game modification source
materials and supporting development resources.

## Supported Versions

Security maintenance is focused on current,
actively maintained project versions.

Older or experimental source snapshots may not
receive security updates.

## Reporting a Vulnerability

Please do not publicly disclose an exploitable
security vulnerability before maintainers have
had an opportunity to investigate.

Preferred reporting method:

1. Open the repository's Security tab.
2. Select "Report a vulnerability" if private
   vulnerability reporting is enabled.
3. Provide a clear reproduction and impact summary.

If private reporting is unavailable, open a
general issue requesting a secure reporting channel.
Do not include exploit details or sensitive data
in that public issue.

## Useful Report Information

- Affected mod or component
- Relevant version or commit
- Description of the vulnerability
- Reproduction steps
- Potential impact
- Suggested mitigation, if available

## Response Process

Reports will be reviewed as maintainer availability
permits.

Valid reports may result in code changes,
documentation updates, or official release updates.

No specific response or remediation timeline
is guaranteed.

## Scope

Examples of relevant security concerns include:

- Unsafe file handling
- Untrusted input processing
- Unexpected script execution
- Credential exposure
- Unsafe dependencies
- Vulnerabilities introduced by mod tooling

Game crashes and ordinary gameplay bugs should
generally be reported through GitHub Issues.

## Official Updates

Security fixes are incorporated into official
CyberStudios releases at maintainer discretion.

Contributors should not publish unofficial
patched mod distributions without authorization
under the applicable license.
